# Smoke Signal

**Smoke Signal** is a demo of a cost-signal layer for Rho. It learns each vendor's normal spend trajectory from transaction history, detects meaningful changes with deterministic statistics, classifies vendors by cost type (usage-scaling, fixed, headcount-scaling, annual, payroll), and explains each change in plain language. An alert fires only when a change is both unusual for that vendor and material relative to monthly spend, so the same rules work from seed through scale up. Claude classifies unknown vendors and writes the explanations, but never decides what fires.

Smoke Signal also reads cash position from Rho's own accounts and turns it into runway. Each material alert carries the weeks of runway it costs if the new rate holds, and the monthly report includes a cash card with runway, net burn, and idle balance, delivered to a named founder by direct message. A settings page gives admins per-cost-type alert thresholds, vendor reassignment to any category, runway buffer and delivery options, and per-vendor opt-in for a read-only Anthropic or OpenAI admin key, reserved for a per-model breakdown.

The trend detection is purely statistical over a few monthly points, so false positives are the main risk. A V2 would tighten it with better growth and runway modeling, learn classification from admin overrides and reactions instead of a static taxonomy, wire the provider keys into real per-model breakdowns, and add mute and recipient rules so team leads see only their own vendors.

It runs on synthetic data shaped like Rho's API schema for a fictional Series A company, Lumen Labs. The output is a web page that mimics Slack: alert cards as new charges arrive, a monthly report when the month closes, threadable follow-up questions on every finding, a transaction records view, and the settings page.

## Tech stack

**Frontend (demo only):** Next.js 16 App Router, React 19, TypeScript, Tailwind 4. State in localStorage. Types generated from the backend's OpenAPI with openapi-typescript. It is a Slack look-alike built to present the demo, not a production surface.

**Backend:** FastAPI on Python 3.12, pandas, numpy, Pydantic, managed with uv. Anthropic SDK with claude-sonnet-5 for vendor classification, narration, and thread answers. Synthetic data generated by a seeded script and committed as JSON in Rho's API schema.

**Hosting:** one Vercel project with two Vercel Services, `web` for Next.js and `api` for FastAPI, joined by rewrites.

**Testing:** pytest, Playwright, and a scenario evaluation script.

**Production into Slack:** Slack Bolt for Python with Block Kit messages, the Events API for threads, and Home tab modals for settings, or delivery through Rho's own Slack app. Frontend reduced to a small Next.js settings app or removed. Postgres via Neon or Supabase on the Vercel Marketplace for overrides, thresholds, open issues, alerts, and reactions. Detection as a daily batch job on Vercel Cron pulling from Rho's transactions and accounts APIs. FastAPI pipeline and Anthropic integration unchanged.
